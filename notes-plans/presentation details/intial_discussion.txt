1. PROJECT CONTEXT
-----------------------------------------------------------------
- Presenter (in real life): me, representing Shomvob (the HR software vendor).
- Actual presenter IN the deck: 300 Ltd's own HR team, presenting UPWARD to
  300 Ltd's management, to convince management to adopt Shomvob's HR system.
  => Tone should read as "here is the solution WE (300 Ltd HR) found for
     OUR problems", not a vendor sales pitch. Shomvob is the enabler, not
     the star of the story. 300 Ltd's pain points are the star.
- 300 Ltd's HR team already knows/likes Shomvob and supplied the
  requirements list (hr_meeting_requirements.txt) - everything on that
  list is confirmed possible in Shomvob's system.
- End goal of THIS project: a Next.js (this project's special/breaking-
  change version - see AGENTS.md, must read node_modules/next/dist/docs/
  before coding) web build where each section = one full viewport
  (100vh/100vw) "slide". At the end, the whole thing gets exported
  page-by-page into a PDF (one viewport = one PDF page). So every section
  must be designed to a fixed frame (treat like a slide, not a
  scrolling webpage).
- Build order agreed: (1) lock content/structure notes [this file],
  (2) build the visual TEMPLATE/system first (empty-ish placeholder
  slides with final look & feel), (3) pour in refined content after,
  which will still be discussed/refined slide by slide.

  This card-grid pattern is the CORE reusable template for the deck.

4. THE CORE CONTENT MODEL (per user point 9 - important)
-----------------------------------------------------------------
The OLD deck's slides 13-19 were organized around SHOMVOB'S MODULES
(Roster, Probation, Offboarding, Dashboard...) shown for their own sake.
The NEW approach for slides 13-23 flips this: every module/feature slide
must explicitly connect to a NAMED PAIN POINT of 300 Ltd, the same way
p8 (Leave Management) already does it:
    Module: "Leave Management"
    Feature: "Bulk approve leaves"
    -> Solves 300 Ltd's concern: "HR needs to select/approve multiple
       leave requests at once" (from hr_meeting_requirements.txt)
So each feature-highlight card in the redesigned slides should be
traceable back to one line in hr_meeting_requirements.txt. This is the
throughline that makes the "template" reusable for slides 13-23 once
finalized content is dropped in.
